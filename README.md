# dsh-Smarter-Subagent-level

为 DSH 的子智能体新增了困难任务模型选项，在创建子智能体时，主对话能按任务难度选子智能体模型，而不必让所有子智能体只能选择较低一阶的模型，可以在对应子智能体中选择比主对话更聪明的模型，并由 AI 自行进行抉择挑选该分配给简单任务模型还是困难任务模型。

你可以配置两份名单：**日常任务模型**负责常规工作；遇到复杂问题，或常规尝试没能解决问题时，主模型可以从**更聪明的模型**名单中挑选成员模型。

## 举个例子：

- 主会话使用 GPT-6.2-Sol，

- 把 GPT-6.1-Terra设为日常模型，

- 把 GPT-6.2-Astra 设为复杂问题模型。

主模型可以让 Terra 成员整理资料，再让 Astra 成员排查难以定位的问题，而主会话仍用 Sol。



<details>
<summary> 安装 </summary>


1. **方式一（推荐）：在 DSH 中直接填包名安装**

打开 **插件与设置 → 安装插件**，在「包名或地址」中粘贴下面的包名，确认安装并启用。无需下载文件或打开终端。

```text
dsh-agent-team-fix
```



2. **方式二：从 GitHub 安装**

在同一安装框中粘贴 `https://github.com/NULLCOLORcat/dsh-Agent-team-fix`，或用命令行安装：

```sh
dsh plugin --profile web add github:NULLCOLORcat/dsh-Agent-team-fix
```

安装后，在 **插件与设置 → dsh-Agent-team-fix** 选择模型并保存，再在需要使用的会话中开启团队模式。

<details>
<summary>设置与技术细节</summary>

| 设置 | 行为 |
| --- | --- |
| 日常任务模型 | 选一个即固定使用；选多个时主模型可自行选择。未指定时使用配置的默认模型和推理强度。 |
| 更聪明的模型 | 可多选。回退开关关闭且名单为空时，不启用困难任务分流。 |
| 高复杂度回退至当前模型 | 打开后，困难任务使用主窗口当前模型及推理强度。困难名单变灰但保留，日常任务不受影响。 |

路由在新建成员时确定，不会替换现有成员，也不是请求失败后的自动重试。检查实际调用时，以新成员首条 `request/header` 的配置为准，不只看成员卡片。

**宿主升级后怎么办？** 请不要强行放行未声明兼容的 DSH 版本。插件运行中一旦检测到不兼容的团队接口，就停止接管后续成员创建，不自动重试或改用其他付费模型。遇到「等待更新」提示时，可继续使用 DSH 原生功能；保留原设置，待安装兼容版本后再重新启用。若 DSH 在加载前就拒绝了插件，插件无法自行发出提醒，请查看宿主插件管理器的不兼容提示。

</details>

<details>
<summary>本地安装、旧版迁移与开发</summary>

- **本地安装：** 在项目根目录运行 `npm pack --ignore-scripts`，将生成的 `.tgz` 安装到目标 profile。
- **从 `dsh-team-terra-ultra` 迁移：** 先停用旧插件，再启用新版，不要同时启用两个路由器。新版沿用原配置入口，保留日常名单、默认模型及推理强度。建议保留旧安装包以便回滚。
- **开发：** `npm test` 运行测试；`npm pack --dry-run` 检查安装包内容。参见[包清单](./package.json)及[发布与市场收录步骤](./docs/PUBLISHING.zh-CN.md)。

</details>
