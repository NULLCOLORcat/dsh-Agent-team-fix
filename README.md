# dsh-Agent-team-fix

针对于 DSH Agent Team的模型调用扩展

为新团队成员指定日常任务模型。遇到难题时，主模型可选用更聪明的模型，或沿用主窗口模型。

## 设置

打开 DSH 的 **插件与设置 → dsh-Agent-team-fix**，直接在插件自己的页面修改并保存，无需进入内部设置。

| 设置 | 对新建本地团队成员的作用 |
| --- | --- |
| 日常任务模型 | 至少选择一个。一个模型固定使用；多个时由主模型选择，也可沿用已配置的默认模型及推理强度。 |
| 更聪明的模型 | 可多选，专供主模型判断为困难、或常规尝试没有有效解决的问题。这里的「更聪明」是用户的指定，不是自动跑分；使用这些模型可能消耗更多额度。 |
| 高复杂度回退至当前模型 | 打开时，困难任务沿用主窗口当前模型，困难名单变灰但保留。关闭且困难名单为空时，不启用困难分流，仍按日常规则。 |

「回退」是创建前的路由选择，不是模型调用失败后的自动重试。修改设置不改写既有会话、已创建成员的请求记录或服务商权限。

## 安装和升级

- 支持 **DSH 0.2.2-rc.5** 的 web 界面和本地 Agent Teams。模型与推理强度须由当前账户的服务商提供。先启用会话的团队模式，再使用成员路由。
- 从 GitHub 安装：`dsh plugin --profile web add github:NULLCOLORcat/dsh-Agent-team-fix`。
- 从本地安装：从项目根运行 `npm pack --ignore-scripts`，用 DSH 插件管理器将生成的 `.tgz` 安装至目标 profile，启用本插件。项目无需编译前端，也不需要配置项目专用密钥。
- 从 `dsh-team-terra-ultra` 迁移：保留日常名单、默认模型及推理强度；关闭旧 bundle 再启用新版，不要同时启用两个路由器。新版沿用原配置入口 `team-terra-ultra`，困难名单初始为空，回退默认关闭。请保留旧安装包，回滚时反向切换。
- 对话能正常打开不能证明成员使用了指定模型；验证路由时看新成员首条 `request/header` 的实际配置，不只看成员卡片。
